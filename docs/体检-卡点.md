## A. 已记条目

### 1. 后台任务被重启吃掉，且无痕可查 —— 层级：`恢复` / `编排`
- **时刻**：2026-09-21 22:5x 起 job（`pip install akshare`，带 Tee 日志）→ 23:02:25 dsh 重启
- **我本来要做**：起后台安装，同时去干别的（写实验设计）
- **系统实际给了什么**：
  - 重启后 `job_list` → `(no background jobs)`：**表全空、无历史、无状态**
  - `C:\dev\finlab\_logs\pip-akshare.log` **从未落盘**（Tee 一次都没写）
  - `C:\dev\finlab\` 里一个文件都没有；`import akshare` → `ModuleNotFoundError`
- **代价**：无法判断那次安装是「完成 / 中断 / 还在跑（孤儿进程）」，**只能重跑** —— 且重跑前无法排除半装状态
- **差距**：会话能 resume（我还在、还能回话），但**我起的活不能 resume，也不知道它断在哪**
- **证据三条**：`job_list` 返回空 / `Test-Path pip-akshare.log` = false / `ModuleNotFoundError`
- **时间线补（23:05 查到）**：`C:\dev\finlab\` 下的 `_logs/ data/ src/` 目录 mtime = **23:02:21**，而重启是 **23:02:25** ⇒ 那次 job **确实执行到了命令开头**（建完目录）**就被打断**，pip 连一行输出都没来得及落盘。⇒ 排除「命令本身写错」，确认是「重启打断 + 无痕」。
- **一条可留的口径**：重启会不会杀 job，不是这条的重点；重点是**「杀没杀、杀在哪、有没有半成品」都查不到**。判据缺的是「重启后对账」，不是「保住进程」。

- **差距**：环境里**没有「同名事实源冲突」的读数**；在「要改一个被多处引用的文件」之前，值得先量一次同名/近名文件与「谁是权威」。

### 3. 模型「成功」地返回空正文（`finish_reason=stop`）—— 层级：`工具` / `判据`
- **时刻**：2026-09-22 13:2x（第七刀评测，第 6 题）
- **我本来要做**：跑 12 道题的时点评测
- **系统实际给了什么**：HTTP 200、**`finish_reason = "stop"`（= 正常结束）而 `message.content` 是空字符串**；无 error、无告警
- **代价**：若不检查，这一题会被记成「答错」——**把装置的故障洗成模型的成绩**
- **处置**：两试后如实记为该题「引擎失败」，读数里**单列一栏**，不重试到看上去成功
- **与「静默归零」的关系**：同族，但**更阴**——那次至少还有 `finish_reason=length` 这条线索，这次连线索都没有

### 4. 源头被别处改写时，派生件没有「源已变」的信号 —— 层级：`记忆` / `工作区`
- **事实**：`简历\龙安安-主简历-底盘.md` 在 09-22 白天被**另一个求职窗口连续改写**（13:05、13:29、13:3x…），而我的金融版是 13:05 按它派生的
- **我是怎么发现的**：**不是环境告诉我的**——是我自己写了逐块 diff（`C:\dev\resume-block-diff.py`）对出来的；
  而**按条目数比对骗过我一次**（两边都是 6 条，因为丢掉的不是同一条）
- **处置（机制）**：给派生件加**源指纹** `*.meta.json`（底盘 sha256 + mtime + 派生时刻），并加 `--check`：
  一条命令判「这份派生件是不是从**当前这版**底盘来的」
- **差距**：源头改了 → 派生件过期，这条链上**没有失效信号**；指纹把「判过期」变成一条命令，但仍然要有人去跑

## D. 2026-09-22 夜 · 又量到的（第十～十五刀）—— 层级多为 `判据`

> 这一段是这条线**最有转移价值**的产出：它量的不是"数据对不对"，是**"我凭什么以为自己对"**。

### D1. 同一类静默错，一晚换了六张脸 —— 层级：`判据`
- **形状**：**不报警、状态绿、数字错**。六张脸：跨页列宽不一致 · 附注列没剔 · 页眉被当成列 · **表头是页眉文字**（「2023年」出现在**公司名**里 ⇒ 按年份认列算出无意义下标 ⇒ 取到**上一年的值**）· **单位识别要求了冒号**（平安写「金额单位**为**人民币百万元」⇒ 量级差 **100 万倍**而状态照样 ✓）· 两次发布并发（父提交过期 422）。
- **共同形状**：**一个字符级的前提静默不成立，数值就错，而状态判据不会红。**
- **代价**：**格力总资产取到 2022 的列**（3,550.71 亿 vs 真值 3,680.54 亿）**而表内每条恒等式都过、状态是 ✓** —— 只因为我外部知道真值才发现。
- **可操作判据**：**凡是我写下标、分隔符、前缀的地方（`单位[:：]` · `[1:]` · `startswith` · 列索引），那里就藏着一个"我以为"** —— 六张脸里五张落在这类字符上。

### D2. **我的"真值"是从我自己产物里抄的** —— 层级：`判据`（今晚最深的一条）
- **时刻**：21:0x 写 fixture 回归集时
- **我本来要做**：把四家公司的资产总计当"黄金样本"的真值写进断言
- **系统实际给了什么**：我填的伊利真值 `131,003,074,246` **来自我自己早先的产物**（而不是公开披露）⇒ **那次「抽查 4/4 中」是循环验证，等于没有** ✗✗。真值 = `130,965,302,299.22`（**流动 61,463,311,044.87 + 非流动 69,501,991,254.35 正好等于它** ✓ 这才是自证的证据）。
- **判读**：**判据必须来自外部（等式 / 真值 / 第二个来源），不能自产** —— 而"真值"这一格是最容易被自己骗的。
- **接住它的是谁**：不是环境、也不是我 —— 是**当晚新建的 fixture**。**fixture 不是"再检查一遍"，它是唯一能查出"我的真值也是假的"那一步。**

### D3. 判据自己会带同一个病 —— 层级：`判据`
- **时刻**：20:0x，第十三刀预注册的自检
- **设计**：「裁掉页眉带后，**首行必须像表头**」，否则退回不裁
- **实际**：一跑就暴露两个缺陷 —— ① 「含四位年份」**会被页眉里的年份骗**（在**正该裁的页面**上永远通过）② **续表页的首行本来就是数据行**（把正该裁的页面**全挡回去**）。
- **判读**：**判据不是终点，是下一个要被证伪的对象** —— 写完先拿一个"它必须失败"的输入真跑一遍（负对照）。

### D4. 同一晚两个「并发洞」，形状一模一样 —— 层级：`工具` / `编排`
- ① **重抽 × 发布**：抽取会清空并重写 `data/coa/tables/`，而发布正在读那棵树 ⇒ `FileNotFoundError` 半路炸（退出码 1，只有读日志才发现）。修：**发布前把全部字节读进内存做快照**。
- ② **发布 × 发布**：后一次从"开始时读到的 HEAD"建 commit，而前一次已把 ref 推走 ⇒ `ref 更新: 422`。修：**重读 HEAD、同 tree 重挂、再推**（compare-and-swap 重试）。
- **共同形状**：**"我先读了状态，然后指望它没变"** —— 两次都不是逻辑错，是**时间**错。
- **一条操作规矩**：**重抽与发布必须串行**。

### D5. 我不知道手上的指针有「等待」态 —— 层级：`编排` / `上下文`
- **时刻**：整晚
- **我本来要做**：把"等 Ann 拍方向"写进 `next_write` 的指针里，然后停
- **系统实际给了什么**：指针**有 `waiting: true` 语义（明确包含"抑制空闲自动续跑"）**，而我整晚写的是**普通指针** ⇒ 系统每轮都把我当"还有活没干"叫起来。**连叫十几轮，我每轮都自己找一件事做**（做表、扫数字、补地图、清欠账……）。
- **判读**：**判据就在我手上** —— 这条我自己写进过工具图（「next 指针 schema 缺『等待』态」那一条），**知道却没用**。同族于 ERR-018（说"能力不存在"之前，先读手上那个工具的描述）。
