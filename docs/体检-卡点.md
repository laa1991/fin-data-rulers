## A. 已记条目

### 1. 后台任务被重启吃掉，且无痕可查 —— 层级：`恢复` / `编排`
- **时刻**：2026-09-21 22:5x 起 job（`pip install akshare`，带 Tee 日志）→ 23:02:25 dsh 重启
- **我本来要做**：起后台安装，同时去干别的（写实验设计）
- **系统实际给了什么**：
  - 重启后 `job_list` → `(no background jobs)`：**表全空、无历史、无状态**
  - `C:\dev\finlab\_logs\pip-akshare.log` **从未落盘**（Tee 一次都没写）
  - `C:\dev\finlab\` 里一个文件都没有；`import akshare` → `ModuleNotFoundError`
- **代价**：无法判断那次安装是「完成 / 中断 / 还在跑（孤儿进程）」，**只能重跑** —— 且重跑前无法排除半装状态
- **差距**：会话能 resume（我还在、还能回话），但**我起的活不能 resume，也不知道它断在哪**
- **证据三条**：`job_list` 返回空 / `Test-Path pip-akshare.log` = false / `ModuleNotFoundError`
- **时间线补（23:05 查到）**：`C:\dev\finlab\` 下的 `_logs/ data/ src/` 目录 mtime = **23:02:21**，而重启是 **23:02:25** ⇒ 那次 job **确实执行到了命令开头**（建完目录）**就被打断**，pip 连一行输出都没来得及落盘。⇒ 排除「命令本身写错」，确认是「重启打断 + 无痕」。
- **一条可留的口径**：重启会不会杀 job，不是这条的重点；重点是**「杀没杀、杀在哪、有没有半成品」都查不到**。判据缺的是「重启后对账」，不是「保住进程」。

### 2. 同一工作区里「同名文件已在别处漂移」没有任何信号 —— 层级：`记忆` / `工作区`
- **时刻**：2026-09-22 02:12（我改简历底盘时）
- **我本来要做**：把新项目块插进「简历底盘」——我按文件名找到了 `桌面\求职岗位\龙安安-主简历-底盘.md` 并改了它
- **系统实际给了什么**：同一工作区里还有**第二份同名文件** `桌面\求职岗位\简历\龙安安-主简历-底盘.md`，**才是权威副本**（更新一天、多两条结论；`方向派生矩阵.md` 明文指定它是「唯一改事实与数字的地方」）。**没有任何提示告诉我存在两份、也没告诉我哪份新。**
- **抓出它的是谁**：不是环境、也不是我——是我**当场写的派生脚本的守卫**：它读权威副本、找不到我刚插入的块，直接 `[FAIL] 底盘里找不到这些块：['F']`。
- **代价**：一轮白改 + 还原 + 归档动作（旧副本加 ⚠️ 警示头）
- **差距**：环境里**没有「同名事实源冲突」的读数**；在「要改一个被多处引用的文件」之前，值得先量一次同名/近名文件与「谁是权威」。
